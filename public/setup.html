← 回到寶物教室

把寶物教室，帶進你的班級。

目前可直接體驗示範版。完成下列設定後，老師與學生就能使用各自帳號，在不同裝置同步資料。

Firebase 專案由你持有。尚未建立專案前，示範資料只存在目前的瀏覽器，不會同步，也不會呼叫 AI。

1. 建立 Firebase 專案

開啟 Firebase Console，按「新增專案」，取一個容易辨識的名稱。記下專案 ID。Analytics 並非本版必要功能。

2. 啟用登入與資料庫

  1. 在專案新增 Web App（網頁應用），複製 Firebase Web 設定。
  2. Authentication → Sign-in method → 啟用 Google 登入，設定專案支援信箱。
  3. Cloud Firestore → 建立資料庫，使用正式／鎖定模式；建議選 asia-east1。
  4. App Check → 登記網頁 App，設定 reCAPTCHA v3，將你的網站網域加入。正式後端要求有效 App Check。

3. 確認部署費用

本系統的 Cloud Functions 需要 Firebase Blaze 方案。請專案擁有者確認計費與預算。老師的 AI Studio 免費額度，和 Firebase 主機／函式費用分開計算。

4. 設定程式與登入部署工具

請有開發經驗的管理者依專案 README 操作。複製 .env.example 成 .env.local，填入 Web 設定及 App Check 公開網站金鑰。

pnpm install
npm install -g firebase-tools
firebase login
firebase use --add

選擇剛建立的專案。不要把教師 Gemini Key 寫在前端的 VITE_ 變數。

5. 設定後端加密

管理者產生 32-byte 隨機 Base64 主金鑰，存入 Firebase Secret Manager。它用來加密老師各自提供的 Gemini 金鑰，不能公開或提交到 GitHub。

node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
firebase functions:secrets:set KEY_ENCRYPTION_KEY

複製 functions/.env.example 為 functions/.env.專案ID。先保留 AI_ENABLED=false，在成人教師工具的適用條件與資料處理方式確認後再啟用。

6. 發布網站

pnpm build
firebase deploy --only firestore:rules,functions,hosting

部署完成會得到 https://你的專案.web.app 網址。確認此網域已列於 Authentication 與 App Check 設定。

7. 指定教師帳號

先讓老師使用網站的 Google 登入，再由管理者從 Authentication 複製老師的 UID，使用具備管理權限的憑證執行：

gcloud auth application-default login
node functions/grant-teacher.mjs YOUR_PROJECT_ID TEACHER_AUTH_UID

老師重新登入後會進入教師工作室。教師權限不能由學生自行選擇。

8. 建班級、邀請學生

老師建立班級，把班級代碼分享給學生。學生使用經學校同意的 Google 帳號登入，填入代碼與課堂暱稱，即可建立自己的學習與收藏紀錄。

9. 教師設定 AI Studio Key

  1. 前往 Google AI Studio API Keys，以教師帳號登入。
  2. 選擇或建立專案，建立專用 API Key。
  3. 查看專案的模型、使用層級與額度；免費額度依專案計算。
  4. 回到「AI 與設定」貼上並安全儲存，再按測試連線。
  5. 在教學與出題／學習觀察中由老師啟動 AI，審閱後才發布內容。

請先閱讀 Google 使用條款。本系統不自動傳送名單身分資料，但自由文字仍需要老師检查；不要傳送敏感資料。

10. 上課前做一次完整測試

用不同帳號確認：老師發幣 → 學生收到 → 夾取與入庫 → 保存房間 → 老師發布任務 → 學生繳交 → 老師批閱。也要確認學生無法讀取他人資料、題目答案或教師金鑰。

本版本供小規模試行：每位老師最多 100 位學生，工作區資料有容量保護。長期全校使用前，需完成資料分拆、歸檔、真機效能與雲端安全驗證。詳見專案 README。

教學與原始碼一併交付。任何 Firebase 金鑰或服務帳戶私鑰都不需要貼到聊天中。
