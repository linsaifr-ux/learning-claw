# 正式營運四項缺口：方案與驗收規格

日期：2026-10-02。基準版本：v0.1.50。這是程式碼與官方資料核對後的設計分析，尚未實作或變更既有部署／課堂資料。承接 release-audit-2026-10-01.md。

## 建議方向與決策前提

保留老師電腦作伺服器、學生上課期間使用網頁。將連線、資料復原、教材內容及 AI 提供者分開設計；老師沒有 AI 額度時仍能從核准題庫組卷、發題、收卷、手動批閱和發幣。免費軟體、免費服務額度、網域／設備成本與營運人工應分開計算，不能承諾未來所有成本皆為零。

目前對免費 Gemini 的假設需先重新確認：官方現行條款（生效日 2026-03-23）限制面向或可能由未滿 18 歲人士存取的 API Client；免費服務亦限制個人／敏感資料輸入，內容可能用於產品改善與人工審閱。「老師操作、學生不直接按 AI」不能單獨當成適用性確認。這不是斷言本案已違規，而是目前缺乏足夠依據可判定適用。需取得供應商明確說明或選擇條款適合的方案；單純拆分網域、增加同意勾選或改用付費金鑰，不會自動消除所有適用條件。

## 一、穩定外網

### 現況與根因

- `desktop/launcher/controller.mjs` 執行 Quick Tunnel，從輸出解析 trycloudflare.com 隨機網址。子程序退出會進入故障處理，目前不是獨立維持本機課堂、背景修復通道的設計。
- `desktop/launcher/main.cjs` 已有防止應用閒置休眠的 powerSaveBlocker；不應把這個現成功能說成尚未實作。合蓋、使用者主動休眠、斷電與網路切換仍需實測。
- 正式 Named Tunnel 解決可持續設定的通道／固定主機名稱，不能讓關機的教師電腦繼續服務，也不等同付費 SLA。

### 方案比較

| 方案 | 使用與成本 | 判斷 |
| --- | --- | --- |
| Quick Tunnel | 無需自備網域，網址可能變動，官方定位測試用途 | 保留試用／故障診斷，不作正式標準通道 |
| 每位老師／機構自備 Cloudflare 帳戶及網域，Named Tunnel | Tunnel 有免費使用選項；可用既有受控網域，否則需網域續費；電腦與網路仍由老師提供 | 第一階段正式版建議，部署與資料責任清楚 |
| 平台提供統一網域與每老師子網域 | 老師不必各買網域，但平台承擔網域、配對控制服務、權杖隔離及維運 | 後續降低安裝門檻；不可把管理整個網域的權杖放進教師程式 |
| 集中雲端主機 | 老師關機仍可服務，但增加主機、資料庫、AI 及維運費用 | 與目前上課才使用的需求相比，可暫緩；無法保證永久免費 |

統一網域若未來採用：每一教師安裝實例分配獨立通道及短期配對碼，完成後只下發該通道憑證；中央服務保存最少路由中繼資料，不集中保存學生作答。停止授權須可撤銷個別通道。這是新控制服務，尚未存在。

### 實作項目

1. 啟動中心新增「固定外網設定」：公開網址、通道憑證、測試、更新／撤銷。憑證不放網址或日誌；優先使用系統安全儲存及受限檔案，避免在程序參數暴露。
2. 學生只收到含班級入口資訊的固定連結；班級邀請碼與網址分離，可輪替邀請碼而不重建所有資料。
3. 本機伺服器與通道狀態分離：本機正常、外網連接中、外網正常、重連中、已下課。通道中斷不應自行終止資料庫服務。
4. 背景重連採退避與隨機延遲；教師主動下課不自動重開。外網健康檢查只傳最少狀態，不能含學生資料；檢查通道在線與 HTTP 可用性，不只看子程序存在。
5. 作答在本機瀏覽器保存有期限的草稿，按帳號／班級隔離、登出清除；處理共用裝置風險。提交使用持久化操作識別碼及結果收據，明確區分「待送出」與「已繳交」。
6. 將目前只在同頁有效的授幣重試擴充到重新整理／斷線情境，伺服器保存 actor、請求摘要、結果與期限，禁止相同識別碼帶不同內容。
7. 大型安裝包繼續由 Release 發布；不把課堂通道當成大型檔案下載服務。3D 網頁資產的傳輸與快取另量測。

### 驗收

提議以 30 人作第一個實課門檻，100 人為壓力情境，兩者不是已承諾容量。Windows 與 Apple Silicon 最低支援規格各跑三場 60 分鐘外網課程，至少兩種學生網路；涵蓋同時登入、作答、保存、發幣與遊戲。測試通道程序退出、30 秒與 2 分鐘斷網、Wi-Fi 切換、瀏覽器重新整理、伺服器重啟與下課。

建議目標（待試行確認）：一般讀写 p95 ≤2 秒，網路恢復後 60 秒內重新可用，無已確認提交遺失、無重複扣／發幣；遊戲結算獨立量測與顯示排隊，不用 HTTP 平均值掩蓋等待。若達不到則降低公告支援人數或改善架構。固定網址通過不代表所有上述項目通過。

## 二、帳號復原、備份與資料刪除

### 教師帳號復原

目前 Email 是本機帳號名稱，不代表已有 Email 寄信或信箱所有權驗證服務。第一階段使用離線復原碼，比新增郵件服務更符合自架與低成本需求。

- 首次設定成功或既有老師重新驗證密碼後，產生高熵復原碼，單次展示，可列印／下載；提醒與電腦、備份分開保管。伺服器保存驗證值，不保存明文。
- 復原從桌面 GUI 進入，經可信 IPC 與限時、單次本機授權；不能僅憑 localhost 或「能開啟程式」就允許重設，也不能讓外網 URL 直接呼叫管理能力。
- 輸入復原碼後設定新密碼（維持至少 8 字元），使舊登入 session、復原碼與未完成的復原請求失效，產生新碼；執行限速並留下不含密碼／復原碼的紀錄。
- 密碼雜湊、API 加密金鑰、備份密碼為不同用途；重設登入密碼不應破壞原收藏／題庫或讓原 API 金鑰無法解密。
- 舊備份可能帶回舊復原碼。還原流程必須強制重新設定復原憑證並保持下課；跨安裝的撤銷如何維持需在遷移格式中處理。
- 密碼和復原碼皆遺失時，不設通用管理員密碼。需預先配置的第二復原證據或明確的人工處理流程；備份本身不是自動破解密碼的方法。

學生姓名＋生日登入可保留原需求，但別把生日當作高強度秘密。建議增加老師審核註冊／重設入口、註冊完成即關閉、班級邀請碼撤銷，以及新裝置登入可選擇老師確認或個別登入碼。若維持完全無額外驗證，必須承認熟人知道生日的冒用風險仍存在。

### 備份與還原介面

目前已在啟動時備份 SQLite 與 server.key；需要補「可用且可理解」的流程：

1. 顯示上次成功備份、版本、大小、驗證結果及位置；備份失敗不能顯示成功。
2. 匯出加密備份包，包含資料庫、必要金鑰、格式版本與檢查碼；以備份專用密碼保護。日常學生資料匯出不可夾帶登入雜湊、API Key 或 server.key。
3. 還原前預覽日期／班級數／資料版本；停止寫入、建立回退點，於暫存目錄驗證與必要遷移，通過後原子替換。失敗保留原資料。
4. 還原後清除 session、保持下課、重新確認復原碼與外網設定。禁止跨老師不知情覆蓋。
5. 定期備份可依需求保留最近 7 份每日與 4 份每週（提案，不是法律保存期限）；磁碟不足顯示阻擋及處理方式。定期演練不同電腦與損壞檔案復原。

### 刪除不是一個 DELETE 按鈕

建立「學生／班級資料管理」，先顯示影響範圍、提供資料匯出，再由老師重新驗證身分並確認刪除。此分析不會替使用者刪資料。

涵蓋：credentials、sessions、學生名單、作答、逐題回饋、AI 草稿與已發布分析、代幣紀錄、遊戲紀錄、收藏、房間、私人方案、創作計畫、作品展投稿／縮圖、匯出暫存及快取。共用課堂題目保留但解除個人關聯；若題幹或題庫自由文字本身含個資，另列待核對，不盲刪其他學生需要的題目。

刪除與背景 AI／遊戲可能同時進行：先撤銷 session、標記刪除版本，取消或拒收舊工作，再於資料庫交易內刪除；任何完成較晚的工作不得重建學生紀錄。SQLite WAL、FTS、日誌與匯出檔也納入清理設計，不能承諾可遠端抹除 SSD 或老師先前自行複製的檔案。

備份需有刪除政策：管理中的舊備份可安全重製排除指定學生或依明示期限過期；保留最少刪除清單，使還原舊備份不復活已刪資料。已匯出的外部副本無法由系統保證刪除，介面須揭露。不要一邊顯示「永久刪除」，一邊建立含完整個資的新永久備份。供應商已收到的內容另受其保存與刪除機制管理，本機刪除不等於第三方刪除。

驗收：刪除前／後跑學生端、老師端、搜尋、匯出、背景工作與舊備份還原測試；相鄰學生完全不受影響。過期復原碼、重播請求、未授權呼叫、錯誤密碼、損壞備份與突然中止還原都需測試。

## 三、全科題庫

### 真正缺口

417 個規劃主題與 2232 筆課綱代碼不是可用題數；現有目錄七至九年級通用主題對應為零。810 筆來源摘要也不能代表三至九年級日常供題能力。教師本機已核准量和隨附公開資料是不同統計，不在此次讀取真人題庫來混算。

### 先做覆蓋矩陣，再補內容

以「年級／學習階段 × 科目 × 通用單元 × 學習目標 × 題型 × 難度」記錄需求量、可用核准量、待審量、授權範圍及缺額。108 課綱若以學習階段定義，跨版本的年級分派應標為編輯規劃並由教師確認，不偽裝成官方逐年級指定。本土語文必須再分語種；藝術、健體、綜合與科技應含作品／實作任務和評分規準，不全改成選擇題。

每題保留可追溯來源／授權版本、課綱與題目修訂版、提示與答案、詳解、單位規則、考點標籤、可接受解法及審核紀錄。閱讀材料的使用範圍、改編與再發布權限分開記錄；已取得的授權應保存證據，不因換包而遺失。

內容來源順序：已取得使用範圍的題庫 → 原創核准題與參數模板 → AI 延伸草稿。批次匯入與 OCR 不自動變成核准；圖片、表格、閱讀篇章須保持題組完整。有疑義題分為辨識、缺圖、答案、解析、範圍、權利資料等原因，不用同一個模糊標籤擋住老師。

### 題數如何訂

用實際出題頻率推算，而不是先喊一個龐大總數。例：一單元每次 10 題、希望三次練習不重複，至少需要 30 道符合本次題型／難度的可用題；再預留約 20% 換題餘量為 36 道。這是供題需求例子，未證明 36 道足以涵蓋每個考點。

每個高頻單元可先定 30–40 題及至少 3 組不同情境，再依覆蓋矩陣調整；藝術等單元改用多份實作任務與規準。假設最後確認 400 個單元、每單元 30 題，約 12,000 題只是量級試算，不是既有量或官方要求。

### 讓老師少審核的出題流程

老師用自然語言描述 → AI／非 AI 表單將要求轉成可檢查的範圍 → 先從核准庫依考點、題型、難度與班級歷史挑題 → 足量即交付可發布草稿，教師整卷預覽，不逐題重複核准 → 不足時列出缺額與替代方案 → 老師選擇開發新題後才 AI 延伸 → 自動驗證 → 只確認新題 → 核准收回題庫。

若既有待審題適合，依原使用者要求可挑入草稿，本次確認後同步核准。新題內容變更即失效重新審核；老師 A 的本機核准不能未經治理直接提升為所有老師共用的官方標準。平台種子題庫應由內容維護者審定、版本化發布，老師自己的改動留在本機分支。

檢索目前已有 SQLite FTS，不因「做 RAG」就必須先買向量資料庫。先做課綱／年級硬篩選、中文同義詞、混合排序及可解釋命中原因；需要向量檢索時再量測增益。建立已知相關題的測試集，檢查 Recall@K 與越界率；RAG 找到來源不等於新生成的答案正確。

## 四、AI 品質與資料使用

### 先決定哪些資料可去哪裡

供應商適用性未確認前，不能把免費 Gemini 當成學生資料處理的正式預設。抽掉姓名、Email、手機號碼只是遮罩：`functions/ai-tasks.mjs` 現在有這些替換，但文章中仍可能包含學校、住址、家庭事件與健康資訊。不能把遮罩叫成已完全匿名。

建議獨立 AI provider 介面，區分公開教材出題、個人作答批閱兩種資料用途。依確認過的服務條款與設定允許／拒絕用途；老師先看將傳送的內容，敏感資訊需移除或改採本機處理。不要在錯誤、分析紀錄或品質測試中保存真實金鑰。

完全不使用外部 API 時：核准題庫、參數化出題、客觀題判分及本機統計可以照常；自由作答以人工批閱為保底。本機模型可列替代方案，但須依教師最低硬體、模型授權、繁中能力與評測結果決定，不能承諾所有 Mac／Windows 都有相同品質與速度。更換雲端供應商或啟用帳單也要確認適用條款，不能只看是否拿得到 API Key。

### 三層驗證

1. 確定性檢查：格式／選項唯一、答案字母、程式計算、方程驗算、單位與量綱、可解範圍、題數與重複題。支援的規則才宣告驗證通過，未知題型必須標示。
2. 語意檢查：題目是否足夠資訊、題意與式子一致、是否有多個合理答案、是否符合年級、來源是否支持詳解。可用第二條推理路徑或第二模型找疑點，但 AI 同意不是獨立正確性證明。
3. 人工標準與發行閘門：只有經驗證的題庫／受限模板可免重複審核；任意 AI 新題仍確認。模板驗收須涵蓋題意、參數限制、單位、邊界、答案與詳解一起產生，不只是更換數字。

### 品質測試集與指標

首輪至少 300 個高風險回歸案例（建議起點，不是全科完成證據）：既有加法錯誤、進位說明不一致、答案全部 B、單位漏寫與錯寫同扣分、成語多解、題庫不足、重複單元換題，以及網路／格式失敗。保留包含「一馬當先但最後第三名」等可能合理語境的案例，避免把動態過程與最後名次硬判矛盾。

擴充時分年級／學習階段、科目、題型、難度建立生成題與學生作答兩套資料；使用原創／授權合成資料，真人資料另需合法適用處理。由領域教師獨立評閱，爭議交第三人裁決；測試集與提示詞開發集分開。模型版本、提示詞、規則與檢索版本固定存證，升級後重跑，不把 AI 自評當黃金答案。

建議的初始發行門檻（需教育團隊確認，並非通用標準）：

| 面向 | 擬議門檻 |
| --- | --- |
| 確定性客觀題 | 標準集預期答案、計算與已支援單位規則全部通過 |
| 新題內容 | 驗收集無重大錯誤；範圍、題意、答案、詳解分開統計；存在歧義即留待確認 |
| 自由作答評分 | 至少 95% 與裁定參考分數相差不超過 5/100，另報各科／題型、重複評分差異及嚴重誤判，不只整體平均 |
| 學生回饋 | 能對應實際作答證據、不憑空指稱人格或疾病；不確定處留給老師，不把教師診斷口吻直接發布學生 |
| 壓力與失敗 | 無額度／模型下架／逾時時保留草稿、不自行發布、不遺失已保存批閱 |

300 案例零重大錯誤也不代表真正錯誤率為零；樣本代表性、每科樣本數與重複執行均需揭露。每個受支援範圍應有自己的驗收狀態，避免某科通過就宣布全科通過。

## 五、開發先後與交付門檻

| 階段 | 可交付成果 | 前置／完成條件 |
| --- | --- | --- |
| A 供應商與資料邊界 | 決策紀錄、AI provider 介面規格、資料用途分類、降級流程 | 確認 Gemini／替代服務適用性；不靠勾選框取代契約條件 |
| B 資料安全基礎 | 復原碼、加密匯出／還原、學生／班級刪除、舊備份刪除重套用 | 隔離測試通過、不碰正式資料；完成背景工作競爭與復原碼撤銷測試 |
| C 穩定連線 | Named Tunnel 設定、獨立重連、明確在線狀態、作答草稿與持久收據 | 可控制的網域／通道資源；外網實課及故障注入達標 |
| D 題庫與評測底座 | 覆蓋矩陣、審核工作台、來源版本、固定標準集與評測報告 | 核准內容與有資格的領域審閱；先高頻單元再擴全科 |
| E 分範圍試行與擴充 | 按科目／單元公布可用範圍、課堂實测及問題追蹤 | 每項達標後才開放相應範圍；包含跨平台真機與發行驗收 |

B、C 與 D 的基礎程式可分批推進；內容整理與人工審閱不能用寫程式的完成率代替。此時不給「幾天完成全科」的日期承諾；先以實際首批整理效率與教師審閱能力估算。域名持有方式、AI 提供者適用性、資料保存政策及內容審閱人力是後續需落實的決策；其他設計與隔離測試可先做。
