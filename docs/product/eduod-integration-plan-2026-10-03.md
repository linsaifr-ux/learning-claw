## 1. 決策摘要

以「開放教育資源支援的備課與補強學習」為教育開放資料組主軸。第一階段整合國家教育研究院愛學網的正式開放清單，讓教材推薦接上教師任務、逐題回饋及補強任務。既有題庫負責評量，AI 協助理解要求與推薦排序，收藏獎勵鼓勵完成學習。影片清單、可出題教材、已核准題目必須分開管理。

第一階段不新增外部付費資料庫或伺服器。延用教師電腦、SQLite、Quick Tunnel 與學生網頁。公開資料搜尋不需要 Gemini Key；複雜要求的 AI 解讀仍使用老師自己的 Key。免費額度受供應商政策及使用量限制，不承諾永遠免費或無限呼叫。

完整全科題庫仍為另一條持續工作：接入開放資源不能消除既有 630 個年級／單元候選缺口，也不能視為全科內容已審定。

## 6. 使用流程與減少教師操作

### 建立任務

沿用現有年級、科目、單元、題數表單。題目按既有三種方式組卷；旁邊顯示「相關教學資源」最多三筆，每筆提供適用階段、推薦依據、時長、來源及原站連結。推薦有三種狀態：範圍符合、待確認範圍、未找到。

老師能勾選本次附上的資源、預览後一起發布，不需跳到另一個管理頁。已核准原題維持免重審；新題或改題維持現有確認機制。未找到資源不阻擋已合格題目的發布，也不塞入無關教材。

### 批改與補強

先由選擇題答案或已確認的評分證據取得「本次需要練習的概念」。AI 分析可以提出概念候選，不能直接寫成學生永久能力標籤。按範圍及概念取得資源，教師在原本回饋視窗一次查看、換選並發布。每個概念最多兩筆，避免堆滿連結。

學生每題回饋下顯示「再練習這個概念」，文字簡短，標示影片時長及將開啟外部網站。資源在發布後固定版本；重新分析只更新教師草稿，不自動替換學生已收到內容。要更新學生內容需教師明確再次發布。

### 獎勵

點開資源不算完成學習，不宣稱知道學生觀看多久。老師可附短題／實作回應作補強任務；沿用既有分數與自訂代幣規則，顯示獎勵來源。課程原獎勵與補強獎勵分開且總額可見。伺服器使用任務、學生及獎勵種類的唯一鍵，重新分析、重整或重送不重複發幣。

## 7. 技術設計（待實作）

在現有 SQLite 及 FTS5 上擴充，首版不引入向量服務。資料量與語意評測證明必要後再考慮向量檢索。

新增模組建議：
- `desktop/open-data-registry.mjs`：固定可用來源、資料集身分、授權及同步設定。
- `desktop/open-data-import.mjs`：下載／CSV 解析／欄位檢查／候選暫存／原子切換。
- `desktop/learning-resources.mjs`：資源查詢、範圍過濾、排序與可解釋推薦。
- `desktop/remediation.mjs`：概念證據、推薦草稿及發布快照。
- `scripts/audit-open-data.mjs`：盤點空值、範圍、授權、去重及同步差異。
- `src/LearningResources.jsx`：嵌入現有建立任務與回饋畫面；不新增重複流程。

核心資料模型：

| 資料表／實體 | 必備欄位 |
|---|---|
| dataset_sources | datasetId、provider、catalogUrl、resourceUrl、metadataLicense、syncPolicy |
| dataset_snapshots | datasetId、snapshotId、fetchedAt、sourceModifiedAt（可空）、sha256、parserVersion、rowCount、validationReport |
| learning_resources | datasetId、providerRecordId、resourceId、snapshotId、canonicalUrl、title、description、subjects[]、stages[]、curriculumCodes[]、duration、assetLicenseRaw、usageCapabilities、rawMetadata |
| resource_scope_reviews | resourceId、sourceRevision、scope、reviewState、reviewer、reviewedAt；教師決定不得冒充官方標籤 |
| resource_links | assignmentId／feedbackRevision、resourceId、snapshotId、matchReason、supportingFields、publishedAt、visibility |
| remediation_tasks | studentId、sourceSubmissionId、conceptId、evidenceQuestionIds、taskId、status；僅本機課堂私有資料 |
| reward_receipts | studentId、taskId、rewardType、amount、requestId；唯一約束與交易 |

來源本身更新不覆寫歷史任務所引用的快照。來源消失或授權狀態變動，停止新增推薦並保留歷史引用說明；既有教師核准不能被同步任務取消或洗掉。

搜尋步驟：固定科目與階段 → 檢查授權用途及停用狀態 → 課綱／概念精確匹配 → 標題／關鍵字與描述 FTS 排序 → 去重 → 返回原因。AI 可在小型候選清單內排序，回傳 ID 必須屬於候選集，不能編造網址、範圍或內容。

搜尋請求只向外部傳送教學關鍵字，不傳學生姓名、生日、帳號或整班紀錄。下載僅允許設定的 HTTPS 官方主機；重新導向亦檢查，設定 timeout、容量限制與欄位數限制，防止 URL 被利用存取本機網路。來源文字視為資料，不執行 HTML 或其中的模型指令。

首次隨包提供經驗收的清單快照及來源說明，老師可手動更新；之後採上課前非阻塞更新。同步先完整驗證再切換索引，失敗沿用最近成功快照，顯示更新日期。公開資料快取可重建，私人推薦／發布資料須納入既有加密備份、帳號復原和刪除流程。刪除學生同時刪其補強任務與私有推薦關聯；不得刪共用公開快取。備份還原也要遵守既有刪除紀錄。

## 8. 失敗處理與相容性

| 狀況 | 預期處理 |
|---|---|
| 無 Gemini Key／額度用完 | 已核准題組卷與本機資料篩選仍可用；AI 解讀按鈕說明原因，保留草稿 |

## 9. 驗收與證据

以下是擬定門檻，尚未測得成果。上游缺料不得靠降低門檻掩飾。

1. 匯入：標準 CSV 換行／引號／空值／重複資料／壞 URL 測試；合法列、隔離列與總列數可對帳。重複同步不增加相同資源；來源更新有版本差異報告。模擬中斷後舊庫可讀。
2. 範圍：建立至少 40 組人工標定查詢，涵蓋 3–9 年級、各主要學科、臺灣台語及至少 10 組預期找不到／不該自動推薦的情境。適用資料不足如實標示，不為湊科目數加入錯配。自動推荐不可超越硬性範圍；資料充足的查詢 Top-3 相關率目標 ≥90%，報告分母、各科結果及分歧。
3. 來源：所有自動推薦可追溯正式資料集與快照；偽造 ID、缺來源或不符用途的項目不發布。欄位重點可在 UI 展開查閱。
4. 教學：由教師檢查錯題概念與教材關聯；找資源成功不等於學習有效。以少量試教觀察補強後同概念不同題表現，記錄樣本及限制，不做未證實的因果宣稱。
5. 操作：建立任務、附教材、批改、發布、學生開啟、補強、授幣完整走一次；關閉重開、重算、換題、撤回、過期登入與手機操作均驗收。
6. 資料安全：學生看不到教師私有分析與 API Key；跨班／跨學生 ID 拒絕；新私有資料隨學生刪除及備份規則處理。
7. 穩定性：冷啟動、無網路、壞下載、來源 404、同步中止、重複發布及併發授幣；舊版本資料升級前備份，失敗可回復。
8. 效能：以具體測試電腦記錄本機查詢 p95，目標 <500ms（不含 Gemini 與外站）；同步不阻塞上課。測不過先修索引，不先增加付費服務。
9. 發行：通過相關自動測試及桌機／平板／手機流程，再建立三平台包。Mac Apple Silicon、Intel、Windows 的真機結果分開列；未測平台不得寫通過。

成果包應含：資料字典、來源與授權清單、快照雜湊、匯入及覆蓋報告、查詢評測集與結果、匿名操作截圖、未解決問題清單、版本號、相關程式與測試紀錄。不得使用真實學生個資錄製競賽影片。

第二階段再加入真實統計資料出題：固定資料年度、資料列及數值單位；以程式計算標準答案；圖表與資料對帳；教師確認首個題型模板。第三階段才擴大語文辭典、台語及多科教材，依授權與教學品質逐批增加。

## 11. 競賽敘事與展示安排

主張：讓分散的公開教材成為可依學習需求找到、可追溯且可用於補強的教學資源，降低教師搜尋與重複備課成本。

概述文件沿用使用者指定八段：前言（問題）、創意描述（連結需求與教材）、功能（真實流程）、特色（來源可追溯與少重審）、工具技術（SQLite／RAG／資料集及實際欄位）、對象（3–9 年級）、環境（教師電腦與學生網頁）、結語（實測與限制）。五頁內以一張資料流圖及一張資料集使用表說清楚，不為展現技術堆列名詞。

三分鐘影片草案：0:00–0:25 教師備課問題；0:25–1:10 選單元、查來源、附教材；1:10–1:55 學生作答及回饋；1:55–2:30 補強與獎勵；2:30–3:00 資料追溯與實測成果。未實作的片段移除，不用動畫假裝真實操作。

衡量優先看：準備一份指定任務所花時間、教師修正次數、推薦相關率、有完整來源的比例、資料缺口比例，以及補強前後的作答變化。先定義量測方式再收數據，不預先填節省百分比。

## 13. 加入學校名錄後的定位與選擇

最新建議主軸：「用開放資料建立可驗證的學習任務，串接 AI 回饋、公開教材與遊戲獎勵」。保留既有專題名稱；在概述中用此句說明 EDUOD 的價值，不必為換組重做品牌。

三項首批核心資料集：國小名錄 6087、國中名錄 6088、愛學網 6318。名錄支援教師自選學校背景及真實資料讀表活動；愛學網支援教材搜尋與補強。學校名錄不含課本版本、教學進度、學生成績或教師身分，因此不能拿學校名稱推測出題範圍。

1. 日常備課：沿用題庫與教師明確選擇的年級／科目／單元，附上經範圍核對的官方教材。
2. 真實資料任務：以固定學年度名錄中的公開資料，建立可重算、可追溯的讀表、分類、比較及統計活動。

名錄選單只是降低輸入成本的輔助功能，單靠它難以展示深入應用。競賽展示應讓資料進入題目、答案核對與學習活動，並能追溯使用的原始資料列。此為本計畫依評分方向作出的產品判斷，不是主辦單位對得獎的保證。

## 16. 更新後的產品與技術規格

### A. 教師建班與學校設定

目前 `src/App.jsx` 建班表單及 `functions/domain.mjs` 的 createClass 只有班名、年級等資料，尚無學校名錄關聯。擴充原有「班級與連線」頁，加入選填的「教學情境」：單一學校、跨校線上班、自訂／不指定。

選單一學校才顯示縣市、國小／國中、學校搜尋；列表显示學校名稱、縣市及年度，避免同名選錯。找不到時可保留自訂名稱，標示非官方匹配，不阻擋上課。線上跨校班不要求全班同校，也不要求學生填校名。學校更換不改學生、班級 ID、邀請連結、現有題目或代幣。

此設定為教師自述的教學背景，非任教驗證。兩位老師選到同一所學校，不共享班級或資料。年級由老師明確設定，不能只靠學制推定。無 API Key、無外網也能搜尋已下載的名錄。

### B. 真實資料任務

在現有建立任務中新增明確入口「用開放資料設計活動」，保留原本一般題庫組卷。首批實作少量完整模板：
- 3–4 年級：讀取經選定的學校表格，分類、比較兩組筆數、計算差；題幹及表格一起提供。
- 5–6 年級：依同一年度／同一資料範圍彙整縣市筆數，製作長條圖及讀表題。
- 7–9 年級：依同一資料快照進行百分比、比較，並辨識「名錄筆數不能證明教育品質或人口因果」等資料限制。

以上為設計候選，適齡及課綱對應仍由模板審閱確認，不宣稱官方為各年級指定。地區由老師選擇，未選學校也能做；跨校班選一個共同活動地區即可。國小／國中名錄必須同年度、分階段清楚顯示，不能無提示混用或把跨年資料相加。

模板引擎負責選資料列、計算答案、單位及產生可核對的詳解；AI 只協助文字表達，不能更換資料列、年度、計算結果或加入資料沒有的事實。先讓教師核准模板的教學範圍與規則，只有經驗收且由確定規則產生的變式才可減少重複審閱；自由生成的 AI 新題維持逐次確認。不能因為數據來自官方就自動核准整道題。

### C. 資料結構與任務證據

在第 7 節共同來源登錄架構上新增：
- `schools`／`school_versions`：sourceId、stage、schoolCode（字串）、academicYear、name、countyCode、countyName、address、website、snapshotId、rawMetadata。
- 班級選填 `schoolContext`：mode、sourceId、schoolCode、academicYear、snapshotId、customName。舊班級預設 unspecified；學生回應不自動包含教師學校聯絡資訊。
- `open_data_templates`：templateId、revision、適用範圍、參數限制、計算規則、單位、審閱狀態。
- 題目附 `dataEvidence`：datasetId、snapshotId、academicYear、selectedRowKeys、filterSpec、aggregation、templateRevision、expectedValue、expectedUnit、materialHash。學生提交前僅取得題幹、教材及來源摘要，不能取得預期答案或計算內部欄位。

來源追溯畫面可重算特定快照的同一結果；歷史題不跟著新年度資料變答案。SQLite migration 先備份，追加欄位預設空值，不强制所有老師補填學校。現有 Firebase 與桌面介面需清楚區分支援範圍；首版以現有桌面伺服器實作，其他運行模式不顯示無法操作的入口。

### D. 教學案例與獎勵展示

主要展示案例選「五年級讀表與比較」：教師建立跨校線上班 → 選擇年度與兩個縣市的名錄資料 → 系統顯示資料範圍、表格及可重算答案 → 發布任務 → 學生答題 → 教師確認概念回饋 → 若有合適愛學網教材才附補強 → 完成補強取得教師設定的代幣 → 夾娃娃收藏。

此案例把三份資料連入同一流程，但不保證每一主題都能找到合適影片。沒有教材時直接顯示缺口，仍可發布題目。參賽錄影用合成班級與學生資料，不展示真實學生與學校的關聯。

## 18. 競賽文件與持續經營

EDUOD 文件將既有八段架構的重心調整為「資料如何變成教學服務」。第 5 段列三項實際使用資料集、使用欄位、轉換方法及來源；第 4 段用可重算答案、歷史快照與免重複核准規則說明特色。尚未實作的項目獨立列後續規劃。
